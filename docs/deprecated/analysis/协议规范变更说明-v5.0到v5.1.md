# ESP32 与服务器通信协议规范变更说明

> 版本：v5.0 → v5.1  
> 更新日期：2026-01-16  
> 适用于：智能猫眼门锁系统

---

## 一、变更概述

本次协议升级主要完成以下内容：

1. **两级确认机制**：新增 `esp32_ack` 消息，区分"命令已收到"和"命令执行完成"
2. **统一错误码**：重新定义错误码体系，与 STM32 错误码映射
3. **log_report 格式变更**：`result` 改为 `status` 字符串，新增 `lock_time` 字段
4. **新增消息类型**：`door_opened_report`、`password_report`
5. **新增事件类型**：`door_closed`、`lock_success`、`bolt_alarm`
6. **字段名统一**：`msg_id` 改为 `seq_id`（兼容旧版）

---

## 二、新增消息类型

### 2.1 esp32_ack（第一级确认）

**用途**：ESP32 收到命令后立即发送，表示"命令已收到，开始处理"。

```json
{
    "type": "esp32_ack",
    "seq_id": "1702234567890_0",
    "code": 0,
    "msg": "received"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| type | string | 固定为 `"esp32_ack"` |
| seq_id | string | **回填 Server 下发的原 ID**（保证消息可追溯） |
| code | int | 固定为 0 |
| msg | string | 固定为 "received" |

> **说明**：`seq_id` 必须与 Server 下发的命令中的 `seq_id` 完全一致，格式由 App 生成，推荐：`时间戳_序号`

### 2.2 door_opened_report（开门日志上报）

**用途**：用户实际开门时上报，与 `log_report`（开锁操作）区分。

```json
{
    "type": "door_opened_report",
    "ts": 1702234567890,
    "data": {
        "method": "finger",
        "source": "outside"
    }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| method | string | 开锁方式（与 log_report 相同） |
| source | string | 开门来源：`outside`/`inside`/`unknown` |

**source 取值说明**：

| source | 说明 | STM32 D1 值 |
|--------|------|-------------|
| `outside` | 室外开门（PIR 检测到人体） | 0x00 |
| `inside` | 室内开门（PIR 未检测到人体） | 0x01 |
| `unknown` | 未知/不适用 | 0xFF |

### 2.3 password_report（密码上报）

**用途**：密码查询结果返回时上报。

```json
{
    "type": "password_report",
    "ts": 1702234567890,
    "data": {
        "password": "123456"
    }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| password | string | 6 位密码（零填充字符串） |

## 三、变更的消息格式

### 3.1 log_report（开锁日志上报）

**旧格式 (v5.0)**：
```json
{
    "type": "log_report",
    "ts": 1702234567890,
    "data": {
        "method": "finger",
        "uid": 5,
        "result": true,
        "fail_count": 0
    }
}
```

**新格式 (v5.1)**：
```json
{
    "type": "log_report",
    "ts": 1702234567890,
    "data": {
        "method": "finger",
        "status": "success",
        "uid": 5,
        "fail_count": 0,
        "lock_time": 0
    }
}
```

**变更说明**：

| 字段 | v5.0 | v5.1 | 说明 |
|------|------|------|------|
| result | bool | 删除 | 改用 status 字符串 |
| status | 无 | string | 新增：`success`/`fail`/`locked` |
| lock_time | 无 | int | 新增：剩余锁定时间（分钟） |

**status 取值说明**：

| status | 说明 | uid 含义 | fail_count | lock_time |
|--------|------|----------|------------|-----------|
| `success` | 开锁成功 | 用户 ID | 0 | 0 |
| `fail` | 认证失败 | 用户 ID（0xFF=无法识别） | 1-5 | 0 |
| `locked` | 设备锁定 | 无意义 | 0 | 剩余锁定时间（分钟） |

### 3.2 ack（执行完成确认）

**旧格式 (v5.0)**：
```json
{
    "type": "ack",
    "msg_id": "cmd_88293",
    "code": 0,
    "msg": "OK"
}
```

**新格式 (v5.1)**：
```json
{
    "type": "ack",
    "seq_id": "1702234567890_0",
    "code": 0,
    "msg": "OK"
}
```

**变更说明**：
- `msg_id` 改为 `seq_id`（兼容旧版 `msg_id`）
- `seq_id` 必须回填 Server 下发的原 ID，保证消息可追溯
- 错误码体系重新定义（见第四节）

## 四、统一错误码定义

### 4.1 新错误码表

| code | 含义 | 说明 |
|------|------|------|
| 0 | 成功 | 操作成功完成 |
| 1 | 设备离线 | ESP32 未连接服务器 |
| 2 | 设备忙 | 正在执行其他操作 |
| 3 | 参数错误 | 命令格式或参数无效 |
| 4 | 不支持 | 不支持的命令或操作 |
| 5 | 超时 | 等待响应超时 |
| 6 | 硬件故障 | 硬件异常或不可用 |
| 7 | 资源已满 | 指纹/NFC 存储已满 |
| 8 | 未认证 | 用户未登录或权限不足 |
| 9 | 重复消息 | seq_id 重复（防重放） |
| 10 | 内部错误 | 未知内部异常 |

### 4.2 与 v5.0 错误码对比

| v5.0 code | v5.0 含义 | v5.1 code | v5.1 含义 |
|-----------|----------|-----------|----------|
| 0 | 成功 | 0 | 成功 |
| 1 | 设备忙碌 | 2 | 设备忙 |
| 2 | 参数错误 | 3 | 参数错误 |
| 3 | 硬件故障 | 6 | 硬件故障 |
| 4 | 超时 | 5 | 超时 |
| 5 | 未授权 | 8 | 未认证 |
| 6 | 资源不足 | 7 | 资源已满 |
| 7 | 不支持 | 4 | 不支持 |

### 4.3 STM32 错误码映射

| STM32 错误码 | 宏定义 | 统一 code |
|--------------|--------|-----------|
| 0x01 | ERR_BUSY | 2 |
| 0x02 | ERR_UNSUPPORT | 4 |
| 0x03 | ERR_PARAM | 3 |
| 0x04 | ERR_FP_FULL | 7 |
| 0x05 | ERR_NFC_FULL | 7 |
| 0x06 | ERR_HARDWARE | 6 |
| 0xFF | ERR_TIMEOUT | 5 |

## 五、新增事件类型

`event_report` 消息新增以下事件：

| event | 说明 | param 含义 | STM32 事件ID |
|-------|------|------------|--------------|
| `door_closed` | 门关闭 | 无 | 0x06 (status=0) |
| `lock_success` | 自动上锁成功 | 无 | 0x06 (status=1) |
| `bolt_alarm` | 锁舌未到位报警 | 无 | 0x06 (status=2) |

> **说明**：这三个事件对应 STM32 的 `EVT_LOCK_STATUS (0x06)` 事件。

## 六、两级确认机制

### 6.1 机制说明

| 级别 | 消息类型 | 发送时机 | 含义 |
|------|----------|----------|------|
| 第一级 | `esp32_ack` | ESP32 收到命令后立即发送 | 命令已收到，开始处理 |
| 第二级 | `ack` | STM32 执行完成后发送 | 命令执行完成 |

### 6.2 流程示例

```
Server                  ESP32                   STM32
 │                       │                       │
 │ 命令 (seq_id=xxx)     │                       │
 │──────────────────────>│                       │
 │                       │                       │
 │ esp32_ack             │ ← 第一级：命令已收到   │
 │ seq_id=xxx            │                       │
 │<──────────────────────│                       │
 │                       │                       │
 │                       │ UART 命令             │
 │                       │──────────────────────>│
 │                       │                       │
 │                       │ UART ACK/结果         │
 │                       │<──────────────────────│
 │                       │                       │
 │ ack (seq_id=xxx)      │ ← 第二级：执行完成     │
 │ code=0/错误码         │                       │
 │<──────────────────────│                       │
```

## 七、字段名变更

| 旧字段名 | 新字段名 | 说明 |
|----------|----------|------|
| `msg_id` | `seq_id` | 消息序列号（兼容旧版） |

> **兼容性**：ESP32 同时支持 `seq_id` 和 `msg_id`，优先使用 `seq_id`。

## 八、消息类型汇总

### 8.1 Device → Server

| 消息类型 | 说明 | v5.1 状态 |
|----------|------|-----------|
| `esp32_ack` | 命令已收到确认 | 新增 |
| `ack` | 命令执行完成确认 | 更新（seq_id、错误码） |
| `status_report` | 状态上报 | 无变化 |
| `event_report` | 事件上报 | 更新（新增事件类型） |
| `log_report` | 开锁日志上报 | 更新（status、lock_time） |
| `door_opened_report` | 开门日志上报 | 新增 |
| `password_report` | 密码上报 | 新增 |
| `user_mgmt_result` | 用户管理结果 | 无变化 |
| `heartbeat` | 心跳（预留） | 无变化 |

### 8.2 Server → Device

| 消息类型 | 说明 | v5.1 状态 |
|----------|------|-----------|
| `face_result` | 人脸识别结果 | 更新（seq_id） |
| `lock_control` | 锁控命令 | 更新（seq_id） |
| `dev_control` | 硬件控制 | 更新（seq_id） |
| `user_mgmt` | 用户管理 | 更新（seq_id） |
| `system` | 系统命令 | 无变化 |
| `heartbeat_ack` | 心跳响应 | 无变化 |

## 九、服务器端适配指南

### 9.1 必须处理的新消息

| 消息类型 | 处理方式 |
|----------|----------|
| `esp32_ack` | 更新命令状态为"处理中" |
| `door_opened_report` | 存储开门日志，转发给 App |
| `password_report` | 同步密码到 App |

### 9.2 必须适配的格式变更

| 消息类型 | 变更内容 |
|----------|----------|
| `log_report` | 解析 `status` 字符串，处理 `lock_time` 字段 |
| `ack` | 使用新错误码体系 |
| `event_report` | 处理新增的 `door_closed`/`lock_success`/`bolt_alarm` 事件 |

### 9.3 建议的 App 端错误提示

| code | 用户提示 |
|------|----------|
| 0 | 操作成功 |
| 1 | 设备离线，请检查网络 |
| 2 | 设备忙，请稍后重试 |
| 3 | 参数错误 |
| 4 | 不支持此操作 |
| 5 | 操作超时，请重试 |
| 6 | 硬件故障，请联系维修 |
| 7 | 存储已满，请先删除 |
| 8 | 请先登录 |
| 9 | 请勿重复操作 |
| 10 | 系统错误，请重试 |
