# ESP32 协议升级说明 (v2.8)

> 更新日期：2026-01-16  
> 适用版本：STM32 协议 v2.8 + ESP32 服务器协议 v5.0

---

## 一、本次修改概述

本次修改主要完成以下内容：

1. **新增 `SendDoorOpenedReport` 方法**：独立上报开门日志
2. **重构 `SendLogReport` 方法**：支持 v2.8 协议的三种状态（成功/失败/锁定）
3. **修复 `NFC_TAP_AGAIN` 枚举错误**：改为正确的 `NFC_REMOVE_CARD`

## 三、API 变更详情

### 3.1 SendLogReport（开锁日志上报）

**旧签名**：
```cpp
void SendLogReport(const std::string& method, int uid, bool result, int fail_count = 0);
```

**新签名**：
```cpp
void SendLogReport(const std::string& method, const std::string& status,
                   int uid, int fail_count = 0, int lock_time = 0);
```

**参数说明**：
| 参数 | 类型 | 说明 |
|------|------|------|
| method | string | 开锁方式：finger/nfc/pwd/remote/key/temp_pwd/face |
| status | string | 状态：success/fail/locked |
| uid | int | 用户 ID（成功时有效，失败时可能为 0xFF 表示无法识别） |
| fail_count | int | 失败次数（1-5，仅 fail 状态有效） |
| lock_time | int | 剩余锁定时间（分钟，仅 locked 状态有效） |

**JSON 格式**：
```json
{
  "type": "log_report",
  "ts": 1234567890,
  "data": {
    "method": "finger",
    "status": "success",
    "uid": 5,
    "fail_count": 0,
    "lock_time": 0
  }
}
```

### 3.2 SendDoorOpenedReport（开门日志上报）【新增】

**签名**：
```cpp
void SendDoorOpenedReport(const std::string& method, const std::string& source);
```

**参数说明**：
| 参数 | 类型 | 说明 |
|------|------|------|
| method | string | 开锁方式：finger/nfc/pwd/remote/key/temp_pwd/face |
| source | string | 开门来源：outside/inside/unknown |

**JSON 格式**：
```json
{
  "type": "door_opened_report",
  "ts": 1234567890,
  "data": {
    "method": "finger",
    "source": "outside"
  }
}
```

## 四、状态码对应关系

### 4.1 RPT_UNLOCK (0xA1) 处理逻辑

| D2 值 | status | uid 含义 | fail_count | lock_time |
|-------|--------|----------|------------|-----------|
| 0x00 | success | 用户 ID | 0 | 0 |
| 0x01-0x05 | fail | 用户 ID（0xFF=无法识别） | D2 值 | 0 |
| 0x06 | locked | 无意义 | 0 | D1 值（分钟） |

### 4.2 RPT_DOOR_OPENED (0xA2) 处理逻辑

| D1 值 | source |
|-------|--------|
| 0x00 | outside（室外开门） |
| 0x01 | inside（室内开门） |
| 0xFF | unknown（未知） |

## 五、已完成的协议升级汇总

以下是从 v2.1 升级到 v2.8 过程中已完成的所有更新：

### 5.1 协议常量

- ✅ `LOCK_PROTOCOL_EMPTY = 0xFF`：空值字段填充

### 5.2 新增枚举

- ✅ `RPT_DOOR_OPENED (0xA2)`：开门日志上报类型
- ✅ `EVT_LOCK_STATUS (0x06)`：关门/上锁状态事件
- ✅ `LockStatusCode`：DOOR_CLOSED, LOCK_SUCCESS, BOLT_ALARM
- ✅ `DoorSource`：OUTSIDE, INSIDE, UNKNOWN
- ✅ `FP_ALREADY_EXISTS (0x06)`：指纹已存在
- ✅ `FP_ID_OCCUPIED (0x07)`：指纹 ID 被占用
- ✅ `NFC_ALREADY_EXISTS (0x06)`：NFC 卡已存在
- ✅ `NFC_ID_OCCUPIED (0x07)`：NFC ID 被占用
- ✅ `UnlockResult`：开锁结果码（0x00-0x06）

### 5.3 两级确认机制

- ✅ `SendEsp32Ack`：第一级确认（命令已收到）
- ✅ `SendAck`：第二级确认（命令执行完成）
- ✅ `PendingCommand` 结构体：待处理命令管理
- ✅ `pending_commands_` 映射表：按 UART TYPE 索引
- ✅ `CleanupPendingCommands`：超时命令清理

### 5.4 命令发送空值填充

- ✅ 所有 `lock_control.cc` 中的命令已使用 `LOCK_PROTOCOL_EMPTY`

### 5.5 事件处理

- ✅ `EVT_LOCK_STATUS` 处理：door_closed, lock_success, bolt_alarm
- ✅ `RPT_UNLOCK` 处理：支持 v2.8 的失败次数和锁定状态
- ✅ `RPT_DOOR_OPENED` 处理：独立上报开门日志
- ✅ 语音播报：认证失败剩余次数、设备锁定时间

### 5.6 服务器通信

- ✅ `SendLogReport`：重构为支持 status 字段
- ✅ `SendDoorOpenedReport`：新增开门日志上报
- ✅ `SendPasswordReport`：密码查询结果上报
- ✅ `SendStatusReport`：环境数据和状态上报
- ✅ `SendEventReport`：事件上报
- ✅ `SendUserMgmtResult`：用户管理结果上报

## 六、服务器端适配指南

服务器需要处理以下新增/变更的消息：

### 6.1 log_report（变更）

```json
{
  "type": "log_report",
  "ts": 1234567890,
  "data": {
    "method": "finger",      // 开锁方式
    "status": "success",     // 新增：success/fail/locked
    "uid": 5,                // 用户 ID
    "fail_count": 0,         // 失败次数
    "lock_time": 0           // 新增：锁定剩余时间（分钟）
  }
}
```

### 6.2 door_opened_report（新增）

```json
{
  "type": "door_opened_report",
  "ts": 1234567890,
  "data": {
    "method": "finger",      // 开锁方式
    "source": "outside"      // 开门来源
  }
}
```

### 6.3 事件类型扩展

`event_report` 新增以下事件：
- `door_closed`：门关闭
- `lock_success`：自动上锁成功
- `bolt_alarm`：锁舌未到位报警

3. **设备锁定场景**：验证 `status=locked` 和 `lock_time` 字段
4. **开门日志场景**：验证 `door_opened_report` 消息
5. **室内/室外检测**：验证 `source` 字段正确性
