# ESP32 自动连接服务器功能

## 📋 功能概述

实现了 ESP32 在联网后自动连接服务器的功能，使用指数退避策略进行重试，确保设备能够可靠地保持与服务器的连接。

## ✨ 核心特性

### 1. **自动连接**

- 设备联网后自动尝试连接服务器
- 无需用户手动触发（唤醒词或按钮）
- 连接成功后持续监控连接状态

### 2. **指数退避重试**

- 连接失败后自动重试
- 使用指数退避算法避免频繁重连
- 添加随机抖动防止多设备同时重连

### 3. **智能判断**

- 只在合适的状态下尝试连接
- 尊重用户主动断开的意愿
- 避免在不适当的时机连接

## 🔧 实现细节

### 架构设计

```
┌─────────────────────────────────────┐
│      Application::Start()           │
│  启动自动连接任务（独立 FreeRTOS 任务）│
└─────────────────────────────────────┘
                ↓
┌─────────────────────────────────────┐
│    AutoConnectLoop() 任务循环        │
│  ┌───────────────────────────────┐  │
│  │ 1. ShouldAutoConnect() 检查   │  │
│  │ 2. OpenAudioChannel() 连接    │  │
│  │ 3. 监控连接状态               │  │
│  │ 4. CalculateRetryDelay() 退避 │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

### 关键参数

| 参数             | 值    | 说明                 |
| ---------------- | ----- | -------------------- |
| **初始延迟**     | 1 秒  | 第一次重试的延迟时间 |
| **最大延迟**     | 60 秒 | 重试延迟的上限       |
| **最大重试次数** | 无限  | -1 表示永不放弃      |
| **任务优先级**   | 2     | 低于主循环（3）      |
| **任务栈大小**   | 4KB   | 2048 \* 2 字节       |

### 指数退避时间表

| 重试次数 | 基础延迟 | 实际延迟（含抖动） |
| -------- | -------- | ------------------ |
| 0        | 1秒      | 0.8-1.2秒          |
| 1        | 2秒      | 1.6-2.4秒          |
| 2        | 4秒      | 3.2-4.8秒          |
| 3        | 8秒      | 6.4-9.6秒          |
| 4        | 16秒     | 12.8-19.2秒        |
| 5        | 32秒     | 25.6-38.4秒        |
| 6+       | 60秒     | 48-72秒            |

### 连接条件检查

`ShouldAutoConnect()` 方法检查以下条件：

1. ✅ 自动连接功能已启用
2. ✅ Protocol 已初始化
3. ✅ 当前未连接服务器
4. ✅ 用户未主动断开连接
5. ✅ 设备处于 Idle 状态
6. ✅ 网络已连接
7. ✅ 未处于监控模式

**只有所有条件都满足时才会尝试连接。**

## 🎯 使用场景

### 场景 1：设备启动后自动连接

```
设备启动 → 联网成功 → 等待 5 秒 → 自动连接服务器
```

### 场景 2：连接断开后自动重连

```
连接断开 → 等待 2 秒 → 尝试重连 → 失败 → 指数退避 → 重试
```

### 场景 3：用户主动断开

```
用户按钮断开 → 设置 user_manually_disconnected_ = true →
自动连接暂停 → 直到下次唤醒词或按钮触发
```

### 场景 4：网络异常恢复

```
网络断开 → 自动连接暂停 → 网络恢复 → 自动连接恢复
```

## 🚀 性能影响

### 资源占用

- **内存**: 4KB 栈空间（独立任务）
- **CPU**: 极低（大部分时间处于延迟状态）
- **功耗**: 可忽略（连接时短暂增加）

### 优化措施

1. 使用独立任务，不占用事件位
2. 分段延迟，及时响应状态变化
3. 指数退避，避免频繁重连
4. 随机抖动，防止多设备同步

## ⚠️ 注意事项

1. **用户体验**
   - 自动连接不会打断用户操作
   - 尊重用户主动断开的意愿
   - 连接状态可在 UI 显示

2. **网络友好**
   - 使用指数退避避免频繁重连
   - 添加随机抖动防止同步风暴
   - 最大延迟限制为 60 秒

3. **状态管理**
   - 只在 Idle 状态下自动连接
   - 避免在监控模式下连接
   - 检查网络状态后再连接

4. **错误处理**
   - 连接失败不会阻塞系统
   - 自动重试机制保证可靠性
   - 详细日志便于问题排查

## 🔄 与超时断开的配合

- **超时断开已禁用**：连接将保持直到主动关闭
- **自动重连启用**：断开后自动尝试重连
- **完美配合**：实现"永久在线"的效果
