# ESP32 ↔ STM32 锁控通信协议规范

> 版本：v2.1  
> 更新日期：2025-12-11  
> 适用于：智能猫眼门锁系统

---

## 1. 物理层参数

| 参数     | 值          |
| :------- | :---------- |
| 波特率   | 9600 bps    |
| 数据位   | 8 位        |
| 校验位   | 无          |
| 停止位   | 1 位        |
| 流控     | 无          |
| 字节序   | 大端模式    |

---

## 2. 协议帧格式

- **总长度**: 7 字节
- **校验**: `Checksum = (CAT + TYPE + D0 + D1 + D2) & 0xFF`

```text
[0xAA] [CAT] [TYPE] [DATA0] [DATA1] [DATA2] [CHECKSUM]
  │      │     │       │       │       │        │
 帧头   大类  指令字    └─── 3字节载荷 ───┘    校验和
```

---

## 3. 类别定义 (CAT)

| CAT      | 宏定义名称 | 方向       | 说明                        |
| :------- | :--------- | :--------- | :-------------------------- |
| **0x00** | `CAT_SYS`  | 双向       | 系统握手 (ACK, NACK)        |
| **0x01** | `CAT_RPT`  | STM → ESP  | 上报 (事件, 状态, 查询结果) |
| **0x02** | `CAT_CMD`  | ESP → STM  | 控制 (开锁, 屏幕, 查询请求) |
| **0x03** | `CAT_USER` | 双向       | 用户管理 (指纹, NFC, 密码)  |

---

## 4. 详细指令表

### 4.1 系统握手 (CAT = 0x00)

> **机制**：ESP32 发送的 `CAT_CMD` 或 `CAT_USER` 指令，STM32 校验无误后**必须**回复 ACK。  
> STM32 主动上报的 `CAT_RPT` 消息，ESP32 **不需要**回复 ACK。

| TYPE     | 宏定义    | D0          | D1     | D2   | 说明           |
| :------- | :-------- | :---------- | :----- | :--- | :------------- |
| **0x01** | `ACK_OK`  | 原指令 TYPE | 0x00   | 0x00 | 执行/接收成功  |
| **0x00** | `ACK_ERR` | 原指令 TYPE | 错误码 | 0x00 | 执行失败       |

**错误码定义 (D1)**：

| 错误码 | 宏定义          | 说明             |
| :----- | :-------------- | :--------------- |
| 0x01   | `ERR_BUSY`      | 设备忙           |
| 0x02   | `ERR_UNSUPPORT` | 不支持的指令     |
| 0x03   | `ERR_PARAM`     | 参数错误         |
| 0x04   | `ERR_FP_FULL`   | 指纹库已满       |
| 0x05   | `ERR_NFC_FULL`  | NFC 卡库已满     |
| 0x06   | `ERR_HARDWARE`  | 硬件故障         |
| 0x07   | `ERR_TIMEOUT`   | 操作超时         |


---

### 4.2 控制与查询 (CAT = 0x02) —— ESP32 发起

| TYPE     | 宏定义       | D0        | D1         | D2    | 说明                                      |
| :------- | :----------- | :-------- | :--------- | :---- | :---------------------------------------- |
| **0x10** | `CMD_LOCK`   | 模式      | 保持秒数   | 0x00  | 01:开锁, 02:关锁; D1=0 默认 3 分钟        |
| **0x11** | `CMD_OLED`   | 图标 ID   | 0x00       | 0x00  | 控制 OLED 显示图标                        |
| **0x12** | `CMD_BEEP`   | 次数      | 频率 ID    | 0x00  | 控制蜂鸣器                                |
| **0x13** | `CMD_SYNC_T` | 时(H)     | 分(M)      | 秒(S) | 同步时间                                  |
| **0x14** | `CMD_LIGHT`  | 模式      | 0x00       | 0x00  | 控制补光灯 (00:自动, 01:开, 02:关)        |
| **0x80** | `Q_SENSORS`  | 0x00      | 0x00       | 0x00  | 查询传感器 (STM32 回复 `RPT_ENV`)         |
| **0x81** | `Q_STATUS`   | 0x00      | 0x00       | 0x00  | 查询状态 (STM32 回复 `RPT_STATE`)         |

**CMD_LOCK 模式 (D0)**：

| D0 值 | 说明   |
| :---- | :----- |
| 0x01  | 开锁   |
| 0x02  | 关锁   |

**CMD_OLED 图标 ID (D0)**：

| D0 值 | 说明         |
| :---- | :----------- |
| 0x00  | 清屏/待机    |
| 0x01  | WiFi 已连接  |
| 0x02  | 云端已连接   |
| 0x03  | 识别中...    |
| 0x04  | 识别成功     |
| 0x05  | 识别失败     |

**CMD_BEEP 频率 ID (D1)**：

| D1 值 | 说明     |
| :---- | :------- |
| 0x01  | 短滴     |
| 0x02  | 长鸣     |
| 0x03  | 报警音   |

**CMD_LIGHT 模式 (D0)**：

| D0 值 | 说明                     |
| :---- | :----------------------- |
| 0x00  | 自动模式（恢复光照控制） |
| 0x01  | 强制开灯                 |
| 0x02  | 强制关灯                 |

> **说明**：STM32 默认根据光照传感器自动控制补光灯。ESP32 可通过此命令远程强制开/关灯，或恢复自动控制模式。

### 4.3 上报与响应 (CAT = 0x01) —— STM32 发起

| TYPE     | 宏定义       | D0        | D1       | D2       | 说明                              |
| :------- | :----------- | :-------- | :------- | :------- | :-------------------------------- |
| **0xA0** | `RPT_EVENT`  | 事件 ID   | 参数     | 0x00     | 事件上报                          |
| **0xA1** | `RPT_UNLOCK` | 开锁方式  | ID/0x00  | 结果     | 本地开锁日志                      |
| **0xB0** | `RPT_ENV`    | 电量%     | 光照 H   | 光照 L   | 环境数据 (Lux = D1<<8 \| D2)      |
| **0xB1** | `RPT_STATE`  | 锁状态    | 灯状态   | 0x00     | 状态上报                          |
| **0xC0** | `RPT_PWD`    | Pwd_H     | Pwd_M    | Pwd_L    | 回复密码查询 (3 字节 Hex)         |

**RPT_EVENT 事件 ID (D0)**：

| D0 值 | 宏定义            | 说明         | D1 含义          |
| :---- | :---------------- | :----------- | :--------------- |
| 0x01  | `EVT_DOORBELL`    | 门铃按下     | 0x00             |
| 0x02  | `EVT_PIR`         | PIR 人体检测 | 持续时间(秒)     |
| 0x03  | `EVT_TAMPER`      | 撬锁报警     | 报警级别(1-3)    |
| 0x04  | `EVT_DOOR_OPEN`   | 门未关超时   | 超时时间(分钟)   |
| 0x05  | `EVT_LOW_BATTERY` | 低电量警告   | 当前电量%        |

**RPT_UNLOCK 开锁方式 (D0)**：

| D0 值 | 宏定义              | 说明           |
| :---- | :------------------ | :------------- |
| 0x01  | `UNLOCK_FINGERPRINT`| 指纹开锁       |
| 0x02  | `UNLOCK_NFC`        | NFC 开锁       |
| 0x03  | `UNLOCK_PASSWORD`   | 密码开锁       |
| 0x04  | `UNLOCK_REMOTE`     | 远程开锁(ESP)  |
| 0x05  | `UNLOCK_KEY`        | 机械钥匙       |

**RPT_UNLOCK 结果 (D2)**：

| D2 值 | 说明                   |
| :---- | :--------------------- |
| 0x00  | 成功                   |
| 其他  | 失败次数               |

**RPT_STATE 状态值**：

| 字段   | 值   | 说明     |
| :----- | :--- | :------- |
| D0     | 0x00 | 锁已关   |
| D0     | 0x01 | 锁已开   |
| D1     | 0x00 | 灯灭     |
| D1     | 0x01 | 灯亮     |

### 4.4 用户管理 (CAT = 0x03)

#### A. 指纹管理

**ESP32 → STM32 指令 (TYPE = 0x10)**：

| D0 (子命令) | D1             | D2   | 说明                 |
| :---------- | :------------- | :--- | :------------------- |
| 0x01        | 期望 ID (0=自动) | 0x00 | 开始录入新指纹       |
| 0x02        | 指纹 ID        | 0x00 | 删除指定 ID 的指纹   |
| 0x03        | 0x00           | 0x00 | 清空所有指纹         |
| 0x04        | 0x00           | 0x00 | 查询指纹数量         |

**STM32 → ESP32 反馈 (TYPE = 0x11)**：

| D0 (状态)   | D1             | D2   | 说明                 |
| :---------- | :------------- | :--- | :------------------- |
| 0x01        | 当前次数(1/2/3)| 0x00 | 请按手指（录入中）   |
| 0x02        | 0x00           | 0x00 | 请抬起手指           |
| 0x03        | 新分配的 ID    | 0x00 | 录入成功             |
| 0x04        | 错误码         | 0x00 | 操作失败             |
| 0x05        | 总数           | 0x00 | 数量反馈             |

#### B. NFC 卡片管理

**ESP32 → STM32 指令 (TYPE = 0x20)**：
> 子命令与指纹相同 (0x01 增, 0x02 删, 0x03 清, 0x04 查)

**STM32 → ESP32 反馈 (TYPE = 0x21)**：
> 状态码与指纹相同

#### C. 密码管理

> 仅支持一个全局密码 (6 位数字，最大 999999 = 0x0F423F)

| TYPE     | 方向       | D0    | D1    | D2    | 说明                           |
| :------- | :--------- | :---- | :---- | :---- | :----------------------------- |
| **0x30** | ESP → STM  | Pwd_H | Pwd_M | Pwd_L | 设置/修改密码                  |
| **0x31** | ESP → STM  | 0x00  | 0x00  | 0x00  | 查询密码 (STM32 回复 `RPT_PWD`)|

**密码编码示例**：
- 密码 "123456" = 123456 = 0x01E240
- D0 = 0x01, D1 = 0xE2, D2 = 0x40

## 5. 关键场景流程

### 场景 1：人脸识别远程开锁（核心流程）

```
1. STM32 检测到门铃按下
   STM → ESP: [AA][01][A0][01][00][00][CS]  (RPT_EVENT: 门铃)

2. ESP32 拍照 → 上传服务器 → 人脸识别成功

3. ESP32 发送开锁命令
   ESP → STM: [AA][02][10][01][00][00][CS]  (CMD_LOCK: 开锁)

4. STM32 执行开锁并回复 ACK
   STM → ESP: [AA][00][01][10][00][00][CS]  (ACK_OK)

5. STM32 上报开锁日志
   STM → ESP: [AA][01][A1][04][00][00][CS]  (RPT_UNLOCK: 远程开锁成功)
```

### 场景 2：查询传感器数据

```
1. ESP → STM: [AA][02][80][00][00][00][82]  (Q_SENSORS)
2. STM → ESP: [AA][01][B0][55][01][2C][33]  (RPT_ENV: 电量 85%, 光照 300Lux)
```

### 场景 3：STM32 自动补光

```
1. STM32 检测到光照 < 阈值，自动开灯
2. STM → ESP: [AA][01][B1][00][01][00][B3]  (RPT_STATE: 锁关, 灯亮)
```

### 场景 4：修改密码为 "123456"

```
1. ESP → STM: [AA][03][30][01][E2][40][16]  (设置密码 123456)
2. STM32 写入 Flash
3. STM → ESP: [AA][00][01][30][00][00][31]  (ACK_OK)
```

### 场景 5：录入指纹（完整交互）

```
1. ESP → STM: [AA][03][10][01][00][00][14]  (开始录入, ID 自动分配)
2. STM → ESP: [AA][00][01][10][00][00][11]  (ACK_OK)
3. STM → ESP: [AA][03][11][01][01][00][16]  (请按手指, 第 1 次)
   -- 用户按压 --
4. STM → ESP: [AA][03][11][02][00][00][16]  (请抬起)
   -- 用户抬起 --
5. STM → ESP: [AA][03][11][01][02][00][17]  (请按手指, 第 2 次)
   -- 用户按压 --
6. STM → ESP: [AA][03][11][03][05][00][1C]  (录入成功, ID=5)
```

### 场景 6：PIR 触发人脸识别

```
1. STM32 PIR 传感器触发
   STM → ESP: [AA][01][A0][02][03][00][A6]  (RPT_EVENT: PIR, 持续 3 秒)

2. ESP32 拍照 → 上传服务器 → 识别

3. 识别成功则开锁（同场景 1 步骤 3-5）
```

### 场景 7：远程控制补光灯

```
1. 服务器下发开灯命令，ESP32 转发
   ESP → STM: [AA][02][14][01][00][00][17]  (CMD_LIGHT: 强制开灯)

2. STM32 执行并回复 ACK
   STM → ESP: [AA][00][01][14][00][00][15]  (ACK_OK)

3. STM32 上报状态变化
   STM → ESP: [AA][01][B1][00][01][00][B3]  (RPT_STATE: 锁关, 灯亮)

4. 恢复自动控制
   ESP → STM: [AA][02][14][00][00][00][16]  (CMD_LIGHT: 自动模式)
```

## 6. 心跳保活（可选）

> 建议 ESP32 每 30 秒发一次心跳，超过 3 次无响应则认为 STM32 离线。

| TYPE     | 宏定义     | D0   | D1   | D2   | 说明           |
| :------- | :--------- | :--- | :--- | :--- | :------------- |
| **0xF0** | `SYS_PING` | 0x00 | 0x00 | 0x00 | ESP32 发起心跳 |
| **0xF1** | `SYS_PONG` | 0x00 | 0x00 | 0x00 | STM32 回复心跳 |

## 7. 注意事项

1. **ACK 机制**：只有 `CAT_CMD` 和 `CAT_USER` 需要 STM32 回复 ACK
2. **超时处理**：ESP32 发送命令后应等待 ACK，超时 1 秒可重试（最多 3 次）
3. **帧同步**：接收端通过检测帧头 0xAA 实现帧同步
4. **校验失败**：校验和不匹配的消息应丢弃
5. **补光灯**：STM32 自动控制，状态变化时主动上报 `RPT_STATE`
