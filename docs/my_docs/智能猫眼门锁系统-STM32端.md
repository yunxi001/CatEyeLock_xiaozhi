# ESP32 ↔ STM32 锁控通信协议规范

> 版本：v2.8  
> 更新日期：2026-01-16  
> 适用于：智能猫眼门锁系统

---

## 1. 物理层参数

| 参数     | 值          |
| :------- | :---------- |
| 波特率   | 9600 bps    |
| 数据位   | 8 位        |
| 校验位   | 无          |
| 停止位   | 1 位        |
| 流控     | 无          |
| 字节序   | 大端模式    |

---

## 2. 协议帧格式

- **总长度**: 7 字节
- **校验**: `Checksum = (CAT + TYPE + D0 + D1 + D2) & 0xFF`

```text
[0xAA] [CAT] [TYPE] [DATA0] [DATA1] [DATA2] [CHECKSUM]
  │      │     │       │       │       │        │
 帧头   大类  指令字    └─── 3字节载荷 ───┘    校验和
```

---

## 3. 类别定义 (CAT)

| CAT      | 宏定义名称 | 方向       | 说明                        |
| :------- | :--------- | :--------- | :-------------------------- |
| **0x00** | `CAT_SYS`  | 双向       | 系统握手 (ACK, NACK)        |
| **0x01** | `CAT_RPT`  | STM → ESP  | 上报 (事件, 状态, 查询结果) |
| **0x02** | `CAT_CMD`  | ESP → STM  | 控制 (开锁, 屏幕, 查询请求) |
| **0x03** | `CAT_USER` | 双向       | 用户管理 (指纹, NFC, 密码)  |

---

## 4. 详细指令表

### 4.1 系统握手 (CAT = 0x00)

> **机制**：ESP32 发送的 `CAT_CMD` 或 `CAT_USER` 指令，STM32 校验无误后**必须**回复 ACK。  
> STM32 主动上报的 `CAT_RPT` 消息，ESP32 **不需要**回复 ACK。

| TYPE     | 宏定义    | D0          | D1     | D2   | 说明           |
| :------- | :-------- | :---------- | :----- | :--- | :------------- |
| **0x01** | `ACK_OK`  | 原指令 TYPE | 0xFF   | 0xFF | 执行/接收成功  |
| **0x00** | `ACK_ERR` | 原指令 TYPE | 错误码 | 0xFF | 执行失败       |

**错误码定义 (D1)**：

| 错误码 | 宏定义              | 说明                 |
| :----- | :------------------ | :------------------- |
| 0x01   | `ERR_BUSY`          | 设备忙/操作进行中    |
| 0x02   | `ERR_UNSUPPORT`     | 不支持的指令         |
| 0x03   | `ERR_PARAM`         | 参数错误             |
| 0x04   | `ERR_FP_FULL`       | 指纹库已满           |
| 0x05   | `ERR_NFC_FULL`      | NFC 卡库已满         |
| 0x06   | `ERR_HARDWARE`      | 硬件故障             |
| 0xFF   | `ERR_TIMEOUT`       | 操作超时             |


---

### 4.2 控制与查询 (CAT = 0x02) —— ESP32 发起

| TYPE     | 宏定义       | D0        | D1         | D2    | 说明                                      |
| :------- | :----------- | :-------- | :--------- | :---- | :---------------------------------------- |
| **0x10** | `CMD_LOCK`   | 模式      | 保持秒数   | 0xFF  | 01:开锁, 02:关锁; D1=0 默认 3 分钟        |
| **0x11** | `CMD_OLED`   | 图标 ID   | 0xFF       | 0xFF  | 控制 OLED 显示图标                        |
| **0x12** | `CMD_BEEP`   | 次数      | 频率 ID    | 0xFF  | 控制蜂鸣器                                |
| **0x13** | `CMD_SYNC_T` | 时(H)     | 分(M)      | 秒(S) | 同步时间                                  |
| **0x14** | `CMD_LIGHT`  | 模式      | 0xFF       | 0xFF  | 控制补光灯 (00:自动, 01:开, 02:关)        |
| **0x80** | `Q_SENSORS`  | 0xFF      | 0xFF       | 0xFF  | 查询传感器 (STM32 回复 `RPT_ENV`)         |
| **0x81** | `Q_STATUS`   | 0xFF      | 0xFF       | 0xFF  | 查询状态 (STM32 回复 `RPT_STATE`)         |

**CMD_LOCK 模式 (D0)**：

| D0 值 | 说明   |
| :---- | :----- |
| 0x01  | 开锁   |
| 0x02  | 关锁   |

**CMD_LOCK 响应规则**：

| 当前状态 | 开锁命令 (D0=0x01) | 关锁命令 (D0=0x02) |
| :------- | :----------------- | :----------------- |
| 已上锁   | 成功触发 → ACK     | 已上锁 → ACK (幂等) |
| 已开锁   | 已开锁 → ACK (幂等) | 成功触发 → ACK     |
| 开锁中   | NACK + `ERR_BUSY`  | 成功触发 → ACK     |
| 上锁中   | 成功触发 → ACK     | NACK + `ERR_BUSY`  |
| 其他状态 | NACK + `ERR_BUSY`  | NACK + `ERR_BUSY`  |

> **说明**：开锁/关锁命令采用幂等设计，重复发送相同命令不会报错。只有在操作进行中时才返回 `ERR_BUSY`。

**CMD_OLED 图标 ID (D0)**：

| D0 值 | 说明         |
| :---- | :----------- |
| 0x00  | 清屏/待机    |
| 0x01  | WiFi 已连接  |
| 0x02  | 云端已连接   |
| 0x03  | 识别中...    |
| 0x04  | 识别成功     |
| 0x05  | 识别失败     |

**CMD_BEEP 频率 ID (D1)**：

| D1 值 | 说明     |
| :---- | :------- |
| 0x01  | 短滴     |
| 0x02  | 长鸣     |
| 0x03  | 报警音   |

**CMD_LIGHT 模式 (D0)**：

| D0 值 | 说明                     |
| :---- | :----------------------- |
| 0x00  | 自动模式（恢复光照控制） |
| 0x01  | 强制开灯                 |
| 0x02  | 强制关灯                 |

> **说明**：STM32 默认根据光照传感器自动控制补光灯。ESP32 可通过此命令远程强制开/关灯，或恢复自动控制模式。

### 4.3 上报与响应 (CAT = 0x01) —— STM32 发起

| TYPE     | 宏定义           | D0        | D1       | D2       | 说明                              |
| :------- | :--------------- | :-------- | :------- | :------- | :-------------------------------- |
| **0xA0** | `RPT_EVENT`      | 事件 ID   | 参数     | 0xFF     | 事件上报                          |
| **0xA1** | `RPT_UNLOCK`     | 开锁方式  | 用户ID   | 结果     | 开锁日志（开锁命令执行时上报）    |
| **0xA2** | `RPT_DOOR_OPENED`| 开锁方式  | 开门来源 | 0xFF     | 开门日志（用户实际开门时上报）    |
| **0xB0** | `RPT_ENV`        | 电量%     | 光照 H   | 光照 L   | 环境数据 (Lux = D1<<8 \| D2)      |
| **0xB1** | `RPT_STATE`      | 锁状态    | 灯状态   | 0xFF     | 状态上报                          |
| **0xC0** | `RPT_PWD`        | Pwd_H     | Pwd_M    | Pwd_L    | 回复密码查询 (3 字节 Hex)         |


**RPT_EVENT 事件 ID (D0)**：

| D0 值 | 宏定义            | 说明         | D1 含义          |
| :---- | :---------------- | :----------- | :--------------- |
| 0x01  | `EVT_DOORBELL`    | 门铃按下     | 0x00             |
| 0x02  | `EVT_PIR`         | PIR 人体检测 | 持续时间(秒)     |
| 0x03  | `EVT_TAMPER`      | 撬锁报警     | 报警级别(1-3)    |
| 0x04  | `EVT_DOOR_OPEN`   | 门未关超时   | 超时时间(分钟)   |
| 0x05  | `EVT_LOW_BATTERY` | 低电量警告   | 当前电量%        |
| 0x06  | `EVT_LOCK_STATUS` | 关门/上锁状态 | 状态码(见下表)   |

**EVT_LOCK_STATUS 状态码 (D1)**：

| D1 值 | 宏定义                    | 说明             |
| :---- | :------------------------ | :--------------- |
| 0x00  | `LOCK_STATUS_DOOR_CLOSED` | 门关闭           |
| 0x01  | `LOCK_STATUS_LOCK_SUCCESS`| 上锁成功         |
| 0x02  | `LOCK_STATUS_BOLT_ALARM`  | 锁舌未到位报警   |

**RPT_UNLOCK 开锁方式 (D0)**：

| D0 值 | 宏定义              | 说明           |
| :---- | :------------------ | :------------- |
| 0x01  | `UNLOCK_FINGERPRINT`| 指纹开锁       |
| 0x02  | `UNLOCK_NFC`        | NFC 开锁       |
| 0x03  | `UNLOCK_PASSWORD`   | 密码开锁       |
| 0x04  | `UNLOCK_REMOTE`     | 远程开锁(ESP)  |
| 0x05  | `UNLOCK_KEY`        | 机械钥匙       |
| 0x06  | `UNLOCK_TEMP_PWD`   | 临时密码开锁   |
| 0x07  | `UNLOCK_FACE`       | 人脸开锁       |

**RPT_UNLOCK 用户ID (D1)**：

| D1 值 | 说明                           |
| :---- | :----------------------------- |
| 0x01-0x28 | 指纹/NFC 用户 ID (1-40)    |
| 0x01-0xFF | 锁定时：剩余锁定时间（分钟） |
| 0xFF  | 无用户 ID（密码/远程开锁/认证失败等） |

**RPT_UNLOCK 结果 (D2)**：

| D2 值 | 说明                   |
| :---- | :--------------------- |
| 0x00  | 成功                   |
| 0x01-0x05 | 失败次数（第 1-5 次失败） |
| 0x06  | 已锁定（认证被锁定）   |

> **说明**：
> - `RPT_UNLOCK` 在开锁命令执行成功后立即上报，用于记录开锁操作日志。
> - 认证成功时：D1=用户 ID（指纹/NFC）或 0xFF（密码/远程），D2=0x00。
> - 认证失败时：D1=0xFF（无用户 ID），D2=失败次数（1-5）。
> - 认证被锁定时：D1=剩余锁定时间（分钟，向上取整），D2=0x06。
> - 锁定策略：连续失败 5 次触发锁定，锁定时间递增（1/3/5/10/30 分钟）。

---

**RPT_DOOR_OPENED 开锁方式 (D0)**：

> 与 `RPT_UNLOCK` 的开锁方式定义相同。

**RPT_DOOR_OPENED 开门来源 (D1)**：

> **说明**：D1 字段用于区分开门来源，基于 PIR 传感器在开门前 5 秒内是否检测到人体。

| D1 值 | 宏定义                 | 说明                           |
| :---- | :--------------------- | :----------------------------- |
| 0x00  | `DOOR_SOURCE_OUTSIDE`  | 室外开门（PIR 检测到人体）     |
| 0x01  | `DOOR_SOURCE_INSIDE`   | 室内开门（PIR 未检测到人体）   |
| 0xFF  | -                      | 未知/不适用                    |

> **说明**：`RPT_DOOR_OPENED` 在用户实际开门时上报（门从关闭变为打开），用于记录开门行为和来源。

**RPT_STATE 状态值**：

| 字段   | 值   | 说明     |
| :----- | :--- | :------- |
| D0     | 0x00 | 锁已关   |
| D0     | 0x01 | 锁已开   |
| D1     | 0x00 | 灯灭     |
| D1     | 0x01 | 灯亮     |

### 4.4 用户管理 (CAT = 0x03)

#### A. 指纹管理

**ESP32 → STM32 指令 (TYPE = 0x10)**：

| D0 (子命令) | D1             | D2   | 说明                 |
| :---------- | :------------- | :--- | :------------------- |
| 0x01        | 期望 ID (0=自动) | 0xFF | 开始录入新指纹       |
| 0x02        | 指纹 ID        | 0xFF | 删除指定 ID 的指纹   |
| 0x03        | 0xFF           | 0xFF | 清空所有指纹         |
| 0x04        | 0xFF           | 0xFF | 查询指纹数量         |

**STM32 → ESP32 反馈 (TYPE = 0x11)**：

| D0 (状态)   | D1             | D2   | 说明                             |
| :---------- | :------------- | :--- | :------------------------------- |
| 0x01        | 当前次数         | 0xFF | 请按手指（录入中）               |
| 0x02        | 0xFF           | 0xFF | 请抬起手指                       |
| 0x03        | 新分配的 ID    | 0xFF | 录入成功                         |
| 0x04        | 错误码         | 0xFF | 操作失败                         |
| 0x05        | 总数           | 0xFF | 数量反馈                         |
| 0x06        | 已存在的 ID    | 0xFF | 指纹已存在（返回已有槽位）       |
| 0x07        | 新分配的 ID    | 原 ID | 指定 ID 已被占用（自动分配新 ID）|

**指纹录入特殊场景说明**：

| 场景 | 条件 | STM32 行为 | 反馈 |
| :--- | :--- | :--------- | :--- |
| 正常录入 | 指定 ID 空闲，指纹未录入 | 存储指纹 | 0x03 + 新 ID |
| 指纹已存在 | 指纹已在其他槽位 | 不重复录入 | 0x06 + 已有 ID |
| ID 被占用 | 指定 ID 已有其他指纹 | 自动分配新 ID | 0x07 + 新 ID + 原指定 ID |
| 自动分配 | D1=0x00，自动选择空闲槽位 | 分配最小空闲 ID | 0x03 + 新 ID |

> **注意**：指纹 ID 范围为 1-40（对外），内部存储索引为 0-39。指纹模块最多支持 40 个指纹。

#### B. NFC 卡片管理

**ESP32 → STM32 指令 (TYPE = 0x20)**：

| D0 (子命令) | D1             | D2   | 说明                 |
| :---------- | :------------- | :--- | :------------------- |
| 0x01        | 期望 ID (0=自动) | 0xFF | 开始录入新卡片       |
| 0x02        | 卡片 ID        | 0xFF | 删除指定 ID 的卡片   |
| 0x03        | 0xFF           | 0xFF | 清空所有卡片         |
| 0x04        | 0xFF           | 0xFF | 查询卡片数量         |

**STM32 → ESP32 反馈 (TYPE = 0x21)**：

| D0 (状态)   | D1             | D2   | 说明                           |
| :---------- | :------------- | :--- | :----------------------------- |
| 0x01        | 0xFF           | 0xFF | 请刷卡（录入中）               |
| 0x02        | 0xFF           | 0xFF | 请移开卡片                     |
| 0x03        | 新分配的 ID    | 0xFF | 录入成功                       |
| 0x04        | 错误码         | 0xFF | 操作失败                       |
| 0x05        | 总数           | 0xFF | 数量反馈                       |
| 0x06        | 已存在的 ID    | 0xFF | 卡片 UID 已存在（返回已有槽位）|
| 0x07        | 新分配的 ID    | 原 ID | 指定 ID 已被占用（自动分配新 ID）|

**NFC 录入特殊场景说明**：

| 场景 | 条件 | STM32 行为 | 反馈 |
| :--- | :--- | :--------- | :--- |
| 正常录入 | 指定 ID 空闲，卡片 UID 未录入 | 存储卡片 | 0x03 + 新 ID |
| UID 已存在 | 卡片 UID 已在其他槽位 | 不重复录入 | 0x06 + 已有 ID |
| ID 被占用 | 指定 ID 已有其他卡片 | 自动分配新 ID | 0x07 + 新 ID + 原指定 ID |
| 自动分配 | D1=0x00，自动选择空闲槽位 | 分配最小空闲 ID | 0x03 + 新 ID |

#### C. 密码管理

> 仅支持一个全局密码 (6 位数字，最大 999999 = 0x0F423F)

| TYPE     | 方向       | D0    | D1    | D2    | 说明                           |
| :------- | :--------- | :---- | :---- | :---- | :----------------------------- |
| **0x30** | ESP → STM  | Pwd_H | Pwd_M | Pwd_L | 设置/修改密码                  |
| **0x31** | ESP → STM  | 0xFF  | 0xFF  | 0xFF  | 查询密码 (STM32 回复 `RPT_PWD`)|
| **0x32** | ESP→STM | Pwd_H | Pwd_M | Pwd_L | 设置临时密码（第1包：密码） |
| **0x33** | ESP→STM | Exp_H | Exp_M | Exp_L | 设置临时密码（第2包：有效期秒） |

**密码编码示例**：
- 密码 "123456" = 123456 = 0x01E240
- D0 = 0x01, D1 = 0xE2, D2 = 0x40

## 5. 关键场景流程

### 场景 1：人脸识别远程开锁（核心流程）

```
1. STM32 检测到门铃按下
   STM → ESP: [AA][01][A0][01][00][FF][CS]  (RPT_EVENT: 门铃)

2. ESP32 拍照 → 上传服务器 → 人脸识别成功

3. ESP32 发送开锁命令
   ESP → STM: [AA][02][10][01][00][FF][CS]  (CMD_LOCK: 开锁)

4. STM32 执行开锁并回复 ACK
   STM → ESP: [AA][00][01][10][FF][FF][CS]  (ACK_OK)

5. STM32 上报开锁日志（开锁命令执行成功）
   STM → ESP: [AA][01][A1][04][FF][00][CS]  (RPT_UNLOCK: 远程开锁, 无用户ID, 成功)

6. 用户开门，STM32 上报开门日志
   STM → ESP: [AA][01][A2][04][00][FF][CS]  (RPT_DOOR_OPENED: 远程开锁, 室外开门)
```

### 场景 2：查询传感器数据

```
1. ESP → STM: [AA][02][80][00][00][00][82]  (Q_SENSORS)
2. STM → ESP: [AA][01][B0][55][01][2C][33]  (RPT_ENV: 电量 85%, 光照 300Lux)
```

### 场景 3：STM32 自动补光

```
1. STM32 检测到光照 < 阈值，自动开灯
2. STM → ESP: [AA][01][B1][00][01][00][B3]  (RPT_STATE: 锁关, 灯亮)
```

### 场景 4：修改密码为 "123456"

```
1. ESP → STM: [AA][03][30][01][E2][40][16]  (设置密码 123456)
2. STM32 写入 Flash
3. STM → ESP: [AA][00][01][30][00][00][31]  (ACK_OK)
```

### 场景 5：录入指纹（完整交互）

```
1. ESP → STM: [AA][03][10][01][00][00][14]  (开始录入, ID 自动分配)
2. STM → ESP: [AA][00][01][10][00][00][11]  (ACK_OK)
3. STM → ESP: [AA][03][11][01][01][00][16]  (请按手指, 第 1 次)
   -- 用户按压 --
4. STM → ESP: [AA][03][11][02][00][00][16]  (请抬起)
   -- 用户抬起 --
5. STM → ESP: [AA][03][11][01][02][00][17]  (请按手指, 第 2 次)
   -- 用户按压 --
6. STM → ESP: [AA][03][11][03][05][00][1C]  (录入成功, ID=5)
```

### 场景 6：PIR 触发人脸识别

```
1. STM32 PIR 传感器触发
   STM → ESP: [AA][01][A0][02][03][00][A6]  (RPT_EVENT: PIR, 持续 3 秒)

2. ESP32 拍照 → 上传服务器 → 识别

3. 识别成功则开锁（同场景 1 步骤 3-5）
```

### 场景 7：远程控制补光灯

```
1. 服务器下发开灯命令，ESP32 转发
   ESP → STM: [AA][02][14][01][00][00][17]  (CMD_LIGHT: 强制开灯)

2. STM32 执行并回复 ACK
   STM → ESP: [AA][00][01][14][00][00][15]  (ACK_OK)

3. STM32 上报状态变化
   STM → ESP: [AA][01][B1][00][01][00][B3]  (RPT_STATE: 锁关, 灯亮)

4. 恢复自动控制
   ESP → STM: [AA][02][14][00][00][00][16]  (CMD_LIGHT: 自动模式)
```

### 场景 8：自动上锁流程

```
1. 用户开门后关门，MPU6050 检测到门关闭
   STM → ESP: [AA][01][A0][06][00][FF][CS]  (EVT_LOCK_STATUS: 门关闭)

2. STM32 启动 15 秒自动上锁倒计时

3. 倒计时结束，STM32 执行上锁（电机反转）

4. PA12 中断触发，电机停止（锁舌弹出到位）

5. STM32 等待 PA15 锁舌确认（30 秒超时）

6a. PA15 触发，上锁成功
    STM → ESP: [AA][01][A0][06][01][FF][CS]  (EVT_LOCK_STATUS: 上锁成功)

6b. 30 秒超时，锁舌未到位报警
    STM → ESP: [AA][01][A0][06][02][FF][CS]  (EVT_LOCK_STATUS: 锁舌报警)
```

### 场景 9：室内/室外开门检测

```
1. PIR 传感器检测到人体（室外有人）
   STM32 记录 PIR 触发时间戳

2. 用户通过指纹开锁，STM32 上报开锁日志
   STM → ESP: [AA][01][A1][01][05][00][CS]  (RPT_UNLOCK: 指纹, 用户ID=5, 成功)

3. 用户开门，STM32 判断开门来源
   开门时间 - PIR 时间 <= 5 秒 → 室外开门

4. STM32 上报开门日志（D1=0x00 表示室外）
   STM → ESP: [AA][01][A2][01][00][FF][CS]  (RPT_DOOR_OPENED: 指纹, 室外开门)

5. 若 PIR 未在 5 秒内触发，则判定为室内开门
   STM → ESP: [AA][01][A2][01][01][FF][CS]  (RPT_DOOR_OPENED: 指纹, 室内开门)
```

### 场景 10：本地指纹开锁完整流程

```
1. 用户按压指纹，STM32 验证成功

2. STM32 执行开锁（电机正转）

3. PA12 中断触发，电机停止（开锁到位）

4. STM32 上报开锁日志
   STM → ESP: [AA][01][A1][01][03][00][CS]  (RPT_UNLOCK: 指纹, 用户ID=3, 成功)

5. 用户开门，MPU6050 检测到门打开

6. STM32 上报开门日志
   STM → ESP: [AA][01][A2][01][00][FF][CS]  (RPT_DOOR_OPENED: 指纹, 室外开门)
```

## 7. ACK 响应规则

> **核心原则**：ACK 尽可能在命令执行完成后回复，以便 ESP32 准确判断命令执行结果。

### 7.1 ACK 响应策略分类

| 策略类型 | 说明 | 适用场景 |
|----------|------|----------|
| **执行后 ACK** | 命令执行完成后回复 ACK/NACK | 即时执行的短命令 |
| **先 ACK 后数据** | 先回复 ACK，再发送数据帧 | 查询类命令 |
| **先 ACK 后上报** | 先回复 ACK，过程通过 Report 帧上报 | 长流程交互命令 |

### 7.2 控制命令 (CAT_CMD) ACK 规则

| 命令 | TYPE | ACK 时机 | 成功响应 | 失败响应 |
|------|------|----------|----------|----------|
| `CMD_LOCK` | 0x10 | 执行后 | ACK (含幂等) | NACK + `ERR_BUSY` |
| `CMD_OLED` | 0x11 | 执行后 | ACK | NACK + 错误码 |
| `CMD_BEEP` | 0x12 | 执行后 | ACK | - |
| `CMD_SYNC_T` | 0x13 | 校验后 | ACK | NACK + `ERR_PARAM` |
| `CMD_LIGHT` | 0x14 | 执行后 | ACK | - |
| `Q_SENSORS` | 0x80 | 先 ACK | ACK + `RPT_ENV` | - |
| `Q_STATUS` | 0x81 | 先 ACK | ACK + `RPT_STATE` | - |

**CMD_LOCK 详细响应规则**：

| 当前状态 | 开锁命令 (D0=0x01) | 关锁命令 (D0=0x02) |
|----------|--------------------|--------------------|
| 已上锁 | 成功触发 → ACK | 已上锁 → ACK (幂等) |
| 已开锁 | 已开锁 → ACK (幂等) | 成功触发 → ACK |
| 开锁中 | NACK + `ERR_BUSY` | 成功触发 → ACK |
| 上锁中 | 成功触发 → ACK | NACK + `ERR_BUSY` |
| 其他状态 | NACK + `ERR_BUSY` | NACK + `ERR_BUSY` |

**说明**：
- `CMD_LOCK`：采用幂等设计，重复发送相同命令返回 ACK；操作进行中返回 NACK + `ERR_BUSY`
- `Q_SENSORS` / `Q_STATUS`：先发 ACK 确认收到查询请求，再发送数据帧

### 7.3 用户管理命令 (CAT_USER) ACK 规则

#### 指纹命令 (TYPE = 0x10)

| 子命令 | D0 | ACK 时机 | 说明 |
|--------|-----|----------|------|
| 录入 | 0x01 | **先 ACK** | 长流程，过程通过 `USER_FP_RPT` 上报 |
| 删除 | 0x02 | 执行后 | 成功 ACK，失败 NACK + `ERR_PARAM` |
| 清空 | 0x03 | 执行后 | 成功 ACK，失败 NACK + `ERR_HARDWARE` |
| 查询数量 | 0x04 | 先 ACK | ACK + `USER_FP_RPT` (0x05) |
| 验证 | 0x05 | **先 ACK** | 长流程，结果通过 `USER_FP_RPT` 上报 |

#### NFC 命令 (TYPE = 0x20)

| 子命令 | D0 | ACK 时机 | 说明 |
|--------|-----|----------|------|
| 录入 | 0x01 | **先 ACK** | 长流程，过程通过 `USER_NFC_RPT` 上报 |
| 删除 | 0x02 | 执行后 | 成功 ACK，失败 NACK + `ERR_PARAM` |
| 清空 | 0x03 | 执行后 | 成功 ACK，失败 NACK + `ERR_HARDWARE` |
| 查询数量 | 0x04 | 先 ACK | ACK + `USER_NFC_RPT` (0x05) |
| 验证 | 0x05 | **先 ACK** | 长流程，结果通过 `USER_NFC_RPT` 上报 |

#### 密码命令

| 命令 | TYPE | ACK 时机 | 说明 |
|------|------|----------|------|
| 设置密码 | 0x30 | 执行后 | 写入 Flash 后发 ACK |
| 查询密码 | 0x31 | 先 ACK | ACK + `RPT_PWD` |
| 临时密码包1 | 0x32 | 执行后 | 暂存后发 ACK |
| 临时密码包2 | 0x33 | 执行后 | 设置完成后发 ACK |

### 7.4 长流程命令特殊说明

以下命令需要用户交互，执行时间不确定（可能 5-30 秒），采用 **先 ACK 后上报** 策略：

| 命令 | 说明 | ACK 含义 | 结果上报 |
|------|------|----------|----------|
| 指纹录入 | 需按压 3 次 | 命令已接收，开始录入流程 | `USER_FP_RPT` (0x03/0x04/0x06/0x07) |
| 指纹验证 | 等待用户按压 | 命令已接收，开始验证流程 | `USER_FP_RPT` (0x03/0x04) |
| NFC 录入 | 等待用户刷卡 | 命令已接收，开始录入流程 | `USER_NFC_RPT` (0x03/0x04/0x06/0x07) |
| NFC 验证 | 等待用户刷卡 | 命令已接收，开始验证流程 | `USER_NFC_RPT` (0x03/0x04) |

**流程示例（指纹录入）**：
```
1. ESP → STM: [AA][03][10][01][00][FF][CS]  (开始录入)
2. STM → ESP: [AA][00][01][10][FF][FF][CS]  (ACK: 命令已接收)
3. STM → ESP: [AA][03][11][01][01][FF][CS]  (请按手指, 第 1 次)
   ... 用户交互过程 ...
4. STM → ESP: [AA][03][11][03][05][FF][CS]  (录入成功, ID=5)
```

### 7.5 ESP32 端超时处理建议

| 命令类型 | 建议超时 | 重试次数 |
|----------|----------|----------|
| 即时命令 | 1 秒 | 3 次 |
| 查询命令 | 2 秒 | 2 次 |
| 长流程命令 | 30 秒 | 不重试 |

## 8. 注意事项

1. **ACK 机制**：只有 `CAT_CMD` 和 `CAT_USER` 需要 STM32 回复 ACK
2. **超时处理**：ESP32 发送命令后应等待 ACK，超时 1 秒可重试（最多 3 次）
3. **帧同步**：接收端通过检测帧头 0xAA 实现帧同步
4. **校验失败**：校验和不匹配的消息应丢弃
5. **补光灯**：STM32 自动控制，状态变化时主动上报 `RPT_STATE`
