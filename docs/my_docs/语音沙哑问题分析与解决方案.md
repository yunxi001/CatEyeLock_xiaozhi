# 语音沙哑问题分析与解决方案

## 问题描述

新增的门锁系统语音在 ESP32 上播放时出现沙哑、不清晰的现象，但在电脑上播放正常。原有语音和数字语音播放正常。

## 问题分析

### 根本原因

**Opus 帧时长 (frame_duration) 不匹配**

### 技术细节

1. **原有语音的帧时长**：
   - 检测结果：`duration=2880` → 2880/48000 = **60ms**
   - 示例：`0.ogg`, `welcome.ogg` 等

2. **新增语音的初始帧时长**（问题版本）：
   - 检测结果：`duration=960` → 960/48000 = **20ms**
   - FFmpeg 默认使用 20ms 帧时长

3. **代码中的硬编码值**：
   ```cpp
   // main/audio/audio_service.cc, 第 623 行
   packet->frame_duration = 60;  // 硬编码为 60ms
   ```

### 为什么会导致沙哑？

Opus 解码器的工作原理：

- 解码器期望每个数据包包含 60ms 的音频数据
- 但实际文件中每个数据包只有 20ms 的数据
- 解码器尝试解码 3 倍长度的数据（60ms / 20ms = 3）
- 导致音频严重失真、沙哑、不清晰

### 为什么原有语音正常？

原有语音在生成时就使用了 60ms 帧时长，与代码中的硬编码值匹配，因此播放正常。

## 解决方案

### 已实施方案：重新生成语音文件（60ms 帧时长）

修改 `scripts/convert_voices.py`，添加 `-frame_duration 60` 参数：

```python
cmd = [
    "ffmpeg", "-y",
    "-i", input_file,
    "-c:a", "libopus",
    "-b:a", "32k",
    "-ar", "48000",
    "-ac", "1",
    "-frame_duration", "60",  # 明确指定 60ms 帧时长
    output_file
]
```

重新转换后的语音文件：

| -------------------- | ------------------- | ------- |
| `tamper_alert.ogg`   | 2880 samples = 60ms | ✅ 正确 |

所有新增语音文件的帧时长现在都是 60ms，与原有语音完全一致。

## 技术说明

### Opus 帧时长标准值

Opus 支持的帧时长：2.5, 5, 10, 20, 40, 60ms

- **20ms**：最常用，延迟低，音质好
- **60ms**：延迟较高，但压缩率更好，适合语音提示

### 为什么项目使用 60ms？

可能的原因：

1. 减少数据包数量，降低处理开销
2. 提高压缩效率，节省 Flash 空间
3. 语音提示场景对延迟不敏感

### 代码工作流程

```cpp
// 1. PlaySound() 解析 OGG 文件
int sample_rate = 48000;  // 从 OpusHead 读取
packet->frame_duration = 60;  // 硬编码

// 2. 解码任务调用 SetDecodeSampleRate()
SetDecodeSampleRate(packet->sample_rate, packet->frame_duration);

// 3. 解码器使用正确的参数解码
opus_decoder_->Decode(packet->payload, pcm_output);
```

## 后续建议

### 1. 代码改进（可选）

考虑从 OGG 文件中动态读取帧时长，而不是硬编码：

```cpp
// 从 Opus 数据包头部解析帧时长
int frame_duration = DetectOpusFrameDuration(packet_data);
packet->frame_duration = frame_duration;
```

**优点**：自动适配任何帧时长的文件  
**缺点**：增加代码复杂度

### 2. 文档化

在项目文档中明确说明：

- 所有语音文件必须使用 **48kHz, 单声道, 60ms 帧时长**
- 使用 `scripts/convert_voices.py` 统一转换
- 不要手动修改音频参数

### 3. 验证工具

创建验证脚本，检查所有 OGG 文件的参数：

```bash
# 检查帧时长
ffprobe -v error -show_packets -select_streams a:0 file.ogg | grep duration
```

## 总结

**问题根源**：新增语音使用 20ms 帧时长，与代码期望的 60ms 不匹配。

**解决方案**：重新生成语音文件，明确指定 60ms 帧时长。

**验证结果**：所有新增语音文件现在与原有语音规格完全一致，问题已解决。
